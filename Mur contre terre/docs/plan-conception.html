Analyse du dépôt de référence

Nommogramme (résistance au feu de profilés métalliques, SIA 263 / EN 1993‑1‑2) donne le patron que ce projet reprend : même séparation des couches, même trio d'interfaces, même chaîne d'empaquetage.

Ce qui se transpose directement

  • Séparation stricte en couches : données (catalogue/paramètres) → physique/mécanique → vérifications normatives → orchestration → interface. Aucune couche ne remonte vers celle qui l'appelle.
  • Objets immuables (@dataclass(frozen=True)) pour toute entrée — géométrie, sol, matériaux, cas de charge — un calcul ne modifie jamais ses entrées.
  • Unités SI strictes en interne (m, N, Pa, rad), conversions kN/m², MPa uniquement aux frontières (saisie, rapport).
  • Traçabilité normative : chaque grandeur intermédiaire citée dans la note de calcul porte sa clause (SIA 267 §5.2 etc.), comme docs/references.md chez Nommogramme.
  • Trois surfaces sans calcul propre : CLI, interface de bureau Tkinter, éventuellement navigateur — toutes appellent la même bibliothèque, jamais l'inverse.
  • Empaquetage : PyInstaller piloté par un .spec, compilé sur un runner Windows GitHub Actions au push d'un tag, avec un --autotest qui ouvre la fenêtre et vérifie que les données embarquées et les imports différés (ici : matplotlib Tk, PIL._tkinter_finder) sont bien présents.
  • Tests de non-régression déposables sans coder : tests/cas_reference.toml chez Nommogramme accueille des cas vérifiés en dehors du code Python ; on reprend l'idée pour vos cas Excel (§11).

Où ce projet diverge nécessairement

  • Un vrai calcul aux éléments finis (poutre sur appuis élastiques/rigides, section variable) remplace la lecture d'abaque — module mecanique/ entièrement nouveau, pas de bibliothèque tierce de calcul de structure : matrices de rigidité assemblées à la main, comme le fait Nommogramme pour la thermique (intégration explicite plutôt que boîte noire).
  • Non-linéarité matérielle incrémentale (M‑N‑EI sécant, chargement par paliers) n'a pas d'équivalent chez Nommogramme — c'est le lot le plus proche, par l'esprit, du solveur thermique pas-à-pas de thermique/solveur.py (mise à jour d'une rigidité à chaque pas jusqu'à convergence).
  • Pas de catalogue figé : ici tout est paramétrique (géométrie, sol, charges) — pas de fichier de données source équivalent au classeur SZS, donc pas de module chargeur.py ; en échange, un format de fichier projet à définir (§4) pour la sauvegarde/chargement demandée en §9 de votre prompt.

Architecture du code

Six paquets, dans l'ordre où un calcul les traverse. Chaque module normatif porte sa clause en docstring, comme chez Nommogramme.

Principes repris de Nommogramme

  • mecanique/ et section_ba/ ne connaissent ni Tkinter ni argparse — l'interface ne fait que traduire des champs de saisie vers des objets donnees/ et afficher un objet résultat.
  • Zéro dépendance obligatoire à l'exécution hors numpy (algèbre linéaire du maillage). matplotlib reste un extra [trace], comme chez Nommogramme, pour garder l'exécutable léger.
  • reportlab ou weasyprint pour l'export PDF, openpyxl pour l'export Excel — extras [export].

Structures de données principales

Cinq dataclasses gelées couvrent toutes les entrées ; un objet Projet les agrège et se sérialise en JSON — c'est le « fichier de données » demandé en §9 de votre prompt (extension .mct).

@dataclass(frozen=True)
class Geometrie:
    hauteur: float          # m
    ep_base: float           # m — épaisseur du mur au pied
    ep_couronnement: float   # m — épaisseur en tête
    debord_semelle: float    # m — côté intérieur
    ep_semelle: float        # m
    # B = ep_base + debord_semelle, utilisée par appui_elastique.py

@dataclass(frozen=True)
class Sol:
    gamma: float; gamma_sat: float | None
    phi: float; c: float; delta: float; beta: float
    type_poussee: TypePoussee        # ACTIF | AU_REPOS
    ks: float | None                 # requis si appui élastique

@dataclass(frozen=True)
class ConditionsAppui:
    pied: TypeAppuiPied              # ENCASTREMENT | RESSORT (kθ auto ou saisi)
    tete: TypeAppuiTete              # LIBRE | APPUI_DALLE

@dataclass(frozen=True)
class CasDeCharge:                    # une entrée de la §5.3 de votre prompt
    nom: str
    categorie: CategorieAction        # G | Q | A
    valeur: float
    psi0: float; psi1: float; psi2: float
    parametres: dict                  # excentricité, étendue, profondeur… selon le type

@dataclass(frozen=True)
class Materiaux:
    beton: Beton                      # fck, fctm, Ecm — classe SIA 262
    acier: Acier                      # B500B — fsk, Es
    enrobage_terre: float; enrobage_interieur: float

@dataclass(frozen=True)
class Projet:
    geometrie: Geometrie; sol: Sol; appuis: ConditionsAppui
    charges: tuple[CasDeCharge, ...]; materiaux: Materiaux
    finesse_maillage: float           # m, longueur d'élément

Objets résultats, également immuables, retournés à chaque étage de calcul : ResultatMecanique (N, V, M, déformée par section), ResultatSection (armature requise, verdict, M‑χ), ResultatNonLineaire (courbe charge‑déplacement, palier de divergence). Chacun garde ses grandeurs intermédiaires pour la note de calcul, à l'image de r.mu_0, r.theta_cr… chez Nommogramme.

Géométrie, maillage, conditions d'appui

Géométrie

Conditions d'appui

L'option « encastrement élastique » calcule kθ = ks·B³/12 par mètre de mur (Winkler, semelle entièrement comprimée) ; la valeur est affichée, modifiable, et un avertissement s'affiche si l'excentricité de N en fondation sort du noyau central.

Implémenté au lot 3 : éléments poutre 2D sans transformation de repère (le mur est droit et vertical, l'axe local coïncide avec l'axe global), section évaluée au milieu de chaque élément. La convention de signe de N/V/M a été calibrée et vérifiée numériquement contre des solutions fermées de RDM (console sous charge transversale, moment ou effort normal en tête, encastrement élastique) — voir l'en-tête de mecanique/solveur_lineaire.py.

Sol et poussée des terres

Coulomb pour Kah et Kph (annexe B), retenu pour intégrer nativement le frottement mur‑sol δ et le talus incliné β déjà prévus en entrée (décision validée, §13). Formulation reprise de votre extrait SIA 261 §4.3.2, cohésion et composante verticale comprises.

e_ah,k = Kah · (Σ γe,k·Δz + g0,k) − 2·c′k·√Kah
SIA 261 §4.3.2.3, éq. (3)
e_av,k = e_ah,k · tan(δk)
éq. (4)
e_ph,k = Kph · (Σ γe,k·Δz + g0,k) + 2·c′k·√Kph
§4.3.2.5, éq. (6)
e_pv,k = e_ph,k · tan(δk)
éq. (7)

Kah = Ka de Coulomb (α = 90° pour un parement vertical ; δ = 0 et β = 0 redonnent Rankine — test de non-régression). Σγe,k·Δz + g0,k est la contrainte verticale effective σ′v(z), déjà couverte par le profil γ/γ′ de part et d'autre de la nappe (§4) — pas de sol multicouche à ajouter.

K0 = (1 − sin φ′k)·(1 + sin β) / cos β (β = 0 → Jaky classique)
§4.3.2.4, éq. (5)

Cohésion — §4.3.2.2

Pour c′k > 0, l'implémentation retient e_ah,k = max(Kah·σ′v − 2·c′k·√Kah ; 5 kN/m²) : la formule complète s'applique partout, mais jamais en dessous du plancher normatif — ce qui revient à admettre c′k = 0 (et la valeur minimale) dans la zone proche de la surface où le calcul théorique deviendrait négatif, sans avoir à résoudre la profondeur critique séparément. Implémenté et testé au lot 2 (geotechnique/poussee.py).

Direction et signe de δk — Figure 1

CasParoi rugueuse, déplacement relatif suffisantParoi lisse / pas de déplacement relatif
Poussée active (δk)+2·φ′k/30
Poussée passive (δk)−φ′k/20

Ces valeurs pré-remplissent δ dans l'interface (mur en béton coulé contre terre ⇒ rugueux par défaut) mais restent modifiables. L'équilibre de toutes les forces parallèles à la paroi est contrôlé : e_av,k (et e_pv,k côté passif si mobilisé) s'ajoutent à l'effort normal N(x) transmis au maillage, pas seulement e_ah,k à l'effort tranchant.

Le choix actif/au repos reste à l'utilisateur, après visualisation des déplacements du mur sous charge ELU — l'interface affiche la déformée avant ce choix, pas après.

Pression hydrostatique

Catégorisée G ou Q au choix de l'utilisateur (décision validée, §13), comme le type de poussée. Un facteur de réduction pour perte de charge (écoulement autour du pied) s'applique à l'intensité, sans changer l'allure triangulaire.

Pression de compactage

Modèle simplifié conforme aux deux seuls paramètres demandés (intensité, profondeur d'application) : plateau constant sur les x premiers mètres, nul au-delà. Un profil enveloppe plus détaillé (Broms/OCDI, croissance puis plateau) pourra le remplacer si vous fournissez la clause SIA 267 correspondante — implémenté ainsi au lot 2, à confirmer au lot 12.

Charges, combinaisons, allure des diagrammes

Combinaisons SIA 260

ELU type 2 : Σ γG,j·Gk,j + γQ,1·Qk,1 + Σ γQ,i·ψ0,i·Qk,i
SIA 260 §4.4.3.2
ELS (fréquent) : Σ Gk,j + ψ1,1·Qk,1 + Σ ψ2,i·Qk,i
SIA 260 §4.4.3.4

Génération automatique en faisant tourner chaque action variable en position dominante ; γ et ψ pré-remplis selon SIA 260/261, modifiables par action, et les combinaisons éditables à la main comme demandé.

Allure attendue des diagrammes de pression sur le mur

Chaque diagramme élémentaire est converti en charges nodales équivalentes sur le maillage (§6) avant assemblage ; les diagrammes affichés en résultat (§7 de votre prompt) sont les enveloppes des combinaisons, pas les diagrammes élémentaires ci-dessus.

9

Section béton armé et non-linéarité M‑N‑EI

Pour chaque section et chaque N donné : équilibre des déformations (Navier‑Bernoulli), lois avancées du béton (parabole‑rectangle + traction jusqu'à fissuration SIA 262 §4.1) et de l'acier (bilinéaire écrouissable, B500B) → moment résistant, courbure χ associée, et rigidité sécante :

EI(x) = M(x) / χ(x)
définition sécante

Chargement incrémental

  1. Charge appliquée par paliers (1 %, …, 100 %, pas paramétrable).
  2. À chaque palier : K assemblée avec l'EI(x) courant de chaque élément → résolution linéaire.
  3. Pour chaque section : M(x) obtenu, EI(x) mis à jour via la loi M‑χ(N) → nouvelle K.
  4. Itération jusqu'à convergence (écart EI sous tolérance) ou divergence détectée (non-convergence après N itérations) — le dernier palier convergé est noté comme charge maximale atteinte.

Sortie : courbe charge–déplacement (tête ou point maximal) en fonction du % de charge, comme demandé en §8 de votre prompt.
